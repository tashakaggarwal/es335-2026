How well it works

Lower log loss is better. A coin flip scores 0.693. Intervals come from resampling whole matches.

How it was built

  1. Parse. Ball-by-ball files from Cricsheet became one row per completed over of each chase: score, wickets, balls left, run rates, recent scoring.
  2. Split by season. Earlier seasons for fitting, 2024 for comparing options, 2025 and 2026 held back for one final test. Rows of a match never end up on both sides.
  3. Build features. Mostly ratios that do not depend on how high-scoring a season is, plus batter, venue, home and form signals built only from earlier matches.
  4. Compare against baselines. A constant guess, a guess by over, and the classic rule "win if the current run rate is at least the required rate".
  5. Try models. Logistic regression, gradient-boosted trees and a small neural network, tuned with cross-validation that keeps each match in one fold.
  6. Pick once, test once. The final model was chosen on 2024 with a rule fixed in advance, refitted on everything before 2025, and scored on the test seasons a single time.

Keeping the future out of the past

Splits follow the calendar
The model is always judged on matches played after the ones it learned from.
History uses earlier matches only
Batter strike rates, venue records and team form count matches strictly before the match date, and were checked against a slow brute-force version.
Preprocessing learns from training rows only
Scaling and filling gaps are fitted inside each cross-validation fold.
The test seasons were scored once
After the model was frozen. If the result had been disappointing, it would still be reported as it is.
